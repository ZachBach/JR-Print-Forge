Design strategy & developer handoff

Everything behind the forge.

The live pages are the specification — this document says why they look the way they do, and what a Next.js team needs to rebuild them without guessing.

Two deliverables ship alongside it: the homepage, and the 3D part viewer with OBJ + GLB export.

01 — Strategy

Proof, not adjectives.

Engineers do not buy "premium quality." They buy a tolerance, a lead time, a material name, and evidence that someone competent looked at their file. Every section on the homepage is therefore built to answer one buying question, in order, and each one hands the visitor a number they can check.

Positioning

A machine shop that thinks in additive — engineering review included, not a print farm with an upload box.

Primary conversion

Quote request with files attached. Every section terminates in a path to it; the estimator removes the price unknown before the form is filled.

Proof surface

The hero is a live WebGPU render, not stock art. It demonstrates capability in the medium the company sells.

Figures to replace before launch: ±0.10 mm tolerance, 12 materials, 100% inspected, $65 setup, and the three testimonials. One business day to quote and three business days to produce are yours and already accurate.

02 — Visual system

Instrument panel, not brochure.

Hairline borders at 8% white, square corners, mono labels in wide tracking, and exactly two accent colors. Blue carries information and interaction; orange carries heat and action. Nothing else gets a color.

Type

Chakra Petch 600/700 for headings and numbers — squared terminals read as machined. IBM Plex Sans 400/500 for prose. IBM Plex Mono for every label, spec chip, readout and eyebrow, always uppercase at 9.5–11px with .16–.30em tracking. Headlines clamp from 30px to 84px; body never below 13.5px.

Visual hierarchy, per section

Mono eyebrow with an index (01 —) → Chakra headline at clamp(30px, 4vw, 52px) → one 34ch support line → the content grid. Grids are 1px-gap hairline lattices on a rgba(255,255,255,.08) background, so the dividers are the background showing through rather than borders that double up.

Only six components need "use client": ForgeStage, PulseSurface, ProcessRail, StatCell, Testimonials, QuoteForm. Everything else renders on the server, which is what keeps the first paint fast despite the 3D hero.

Pricing is a pure function. estimate(input) returns unit, setup, low, high and shipBy from the same tables the server action uses, so the number in the panel and the number in the email can never drift.

04 — Page wireframe

Eight blocks, one job each.

01
Hero — 92vh, copy left, forge right

Headline, subhead, two CTAs over a live anvil-and-hammer render with the JR wordmark bottom-right. A gradient scrim keeps the left column at 4.5:1 contrast; the cursor burns a hole through the CAD grid. Footer strip prints the real renderer path and vertex count.

02

Each card carries two spec chips so the capability is measurable. Hover fades in a hatch layer masked to the cursor.

03

Scroll-triggered: each cell rises 18px into place and an ember bar wipes across its top edge. Durations are the commitment, in mono ember.

04
Portfolio — four 4:3 tiles

Photo underneath, blueprint grid on top, cursor wipes the CAD away — the CAD-to-print transformation as an interaction rather than a claim. Slots are drop targets today; swap for next/image on build.

05

Two ember numbers (the promises) and four blue ones (the capabilities). Numbers live in the markup so they are correct with JS disabled.

06
Testimonials — single card, manual advance

No autoplay: quotes are read, not watched. A scanline layer sweeps under the cursor; three rules act as position.

07
Quote — form left, live estimate right

Seven numbered fields; the estimate panel updates on every change and states plainly that it is non-binding. Tolerance FAQ sits beside it to kill the last objection. Submit reveals your confirmation copy verbatim.

08
Footer — contact, services, social, CTA

Ends on the renderer path, which is the same honesty the rest of the page trades on.

05 — Animation specification

Machined, not bouncy.

One easing curve for entrances — cubic-bezier(.2,.7,.2,1) — no overshoot, no spring. Nothing animates twice, nothing animates on scroll-out, and every effect below is gated on prefers-reduced-motion.

06 — PulseMask integration

One primitive, three modes.

The mask is a brand behaviour, not a decoration: the cursor is an inspection light, and what it uncovers is always the real thing under the drawing. Every instance is the same CSS mask driven by two custom properties written from one pointer handler — never React state, so moving the cursor never re-renders a component.

Wipe

Overlay is hidden inside the circle. Hero grid, portfolio CAD layer.

transparent 0 34%, #000 88%
Reveal

Overlay exists only inside the circle. Service-card scan, testimonial sweep.

#000 0 46%, transparent 92%
Shock

The same idea in the shader: a ring expanding from the hammer's impact across the wordmark.

smoothstep(.05, 0, |d − t|) 
// components/PulseSurface.tsx  (client)
const MASK = {
  wipe:   'radial-gradient(circle var(--pm-r) at var(--mx) var(--my), transparent 0 34%, #000 88%)',
  reveal: 'radial-gradient(circle var(--pm-r) at var(--mx) var(--my), #000 0 46%, transparent 92%)',
};

// one rAF-throttled handler per surface; writes vars, never state
const onMove = (e: React.PointerEvent) => {
  const b = e.currentTarget.getBoundingClientRect();
  const el = e.currentTarget as HTMLElement;
  el.style.setProperty('--mx', `${((e.clientX - b.left) / b.width) * 100}%`);
  el.style.setProperty('--my', `${((e.clientY - b.top) / b.height) * 100}%`);
};

Touch and keyboard. With no pointer there is no spotlight, so the default variable values (72% / 46%, radius 200px) must leave a composition that reads on its own — on coarse pointers the overlay drops to 55% opacity and stays static. The reveal is never the only way to reach information.

Radius and kill switch. Both are exposed as tweaks on the live homepage (mask radius 80–420px, PulseMask on/off) — keep them as props in the rebuild so the effect can be tuned or disabled per section without a code change.

07 — The forge stage

WebGPU, TSL, and an honest readout.

three.js r184 WebGPURenderer, loaded by absolute URL so TSL comes from the same module instance — a second copy of three in one page is the thing never to do. Geometry is built with geo-lib (revolve, tube, roundedBox); every surface is a TSL node material composed from tsl-lib (fbm, warp, stripes, ramp, fireRamp, fresnel, horizonBand), with brand colors coming only from a palette module, never a hex literal in material code.

FLAME

Single-pass volumetric raymarch: 26 steps through an AABB, height-sheared fbm for density, emission integrated front-to-back with Beer–Lambert absorption, coloured by fireRamp.

WORDMARK

Slab J and R as bezier shapes, extruded and bevelled, then midpoint-subdivided to ~100k vertices so the vertex stage can carry molten swell and the strike ripple.

FRAMING

The camera renders a window onto a larger virtual frame via setViewOffset, so the rig lands in the right third at any aspect and clears the readout strip — no lookAt guesswork.

BUDGET

Paused when off-screen, pixel ratio capped at 2, reduced-motion freezes the swing. No WebGPU adapter falls back to the WebGL2 backend; a failed boot degrades to a CSS gradient and the strip says so.

In Next.js, mount it with dynamic(() => import('./forge/Stage'), { ssr: false }) behind an IntersectionObserver, so the ~600KB of three never touches the critical path and LCP stays the headline.

09 — Conversion & launch

Nine changes that pay for themselves.

  1. Keep the estimator above the form on mobile — price uncertainty, not form length, is what stops an upload.
  2. Accept the file before asking for the email. Attachment first, contact second, always.
  3. Say "quote in 1 business day" in the hero readout too, not only in the process rail.
  4. Add a reorder link in the confirmation email that pre-fills the last job — repeat print work is the margin.
  5. Instrument four events: upload started, estimate changed, form submitted, quote approved. Anything else is noise.
  6. Give every portfolio tile a material and a lead time in the caption once real photos land. Categories alone do not convert engineers.
  7. Offer a "not sure which material" option in the select that routes to a human — unsure visitors abandon selects.
  8. Publish the tolerance FAQ as its own indexable page; it is the highest-intent search on this list.
  9. Keep the honest renderer line in the footer. Technical buyers notice who tells the truth about small things.
SEO

One h1, sections in document order, Organization + Service + FAQPage JSON-LD, per-service pages later. Metadata in layout, OG image from a static render of the hero.

Accessibility

Body text at 4.5:1 or better against the scrim, visible 2px blue focus rings, labels tied to every input, 44px minimum targets, reduced-motion honoured, no information available only through the mask.

Performance

Self-host the three font families as woff2 subsets; defer the 3D bundle; next/image with AVIF for portfolio photos; no analytics before consent. Target LCP under 2.0s on a mid-range laptop with the hero deferred.
